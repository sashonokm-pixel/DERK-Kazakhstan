# DERK: архитектура и научный протокол

## Слои
1. UI: Streamlit, два режима в едином приложении.
2. Аналитика: pandas, Plotly, агрегация только наблюдений.
3. Данные v0.1: CSV с контролируемой схемой, явными статусами верификации.
4. Геоданные v0.1: центры регионов; v0.2: GeoJSON официальных границ с проверенной лицензией.
5. Развёртывание: GitHub + Streamlit Community Cloud либо корпоративный сервер.

## Целевая схема PostgreSQL (v0.2)
- `regions(id, name_ru, code, geometry, geometry_source, geometry_license)`
- `ethnic_groups(id, standardized_name, classification_source)`
- `platforms(id, name, homepage)`
- `resources(id, platform_id, url, public_name, stated_affiliation, status)`
- `observations(id, resource_id, region_id, ethnic_group_id, observed_at, language, topic, followers_public, source_url, captured_by, verification_status, reviewer_id, reviewed_at)`
- `audit_log(id, actor_id, action, target_id, at)`

## Исследовательский протокол
- Единица анализа: открытый ресурс/сообщество с публично выраженной этнокультурной принадлежностью; не отдельный человек.
- Критерии включения: доступная публичная ссылка, дата проверки, воспроизводимая методика атрибуции, соответствие исследовательской территории.
- Различать территорию ресурса, аудиторию ресурса и проживание представителей этноса. Не выводить место проживания из языка публикации.
- Не выводить этническую принадлежность человека из имени, фотографии, языка, профиля или модели AI.
- Отдельно хранить отсутствие наблюдений, отсутствие доступа и подтверждённый нулевой результат.
- Метрики (число ресурсов, активность, подписчики) публиковать с оговоркой о платформенных ограничениях и смещении выборки.
- Индекс репрезентации не рассчитывать без заранее утверждённой формулы, знаменателя, нормализации и проверки устойчивости.
- Данные соцсетей собирать только законными методами с учётом условий платформ и защиты персональных данных.

## Дорожная карта
1. v0.1: публичный режим, аналитический режим, CSV, фильтры, карта точек, экспорт.
2. v0.2: GeoJSON полигонов, PostgreSQL, аутентификация, роли редактора и рецензента, сохранение и журнал изменений.
3. v0.3: загрузчики официальной статистики, реестр публичных ресурсов, процедура двухэтапной верификации, метаданные источников.
4. v1.0: публичный портал, научные методики и отчёты, API, тестирование безопасности, резервное копирование, деплой на инфраструктуре университета.

## v0.2
Ручной ввод через Streamlit form, редактирование/удаление через data_editor, импорт/экспорт CSV. Сохранение ограничено сессией; для облачного постоянного хранения нужен backend БД и авторизация.
